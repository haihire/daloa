## 14:59 admin 폴더 기능별 재구성 — 조사

**요청**: `server/src/admin` 폴더가 flat하게 여러 기능이 섞여 있음. 기능별 폴더에 module/service/controller가 함께 있도록 정리. 필요 시 client router도 수정.

**현재 구조 (flat, 24개 파일)**: admin-auth/cache/characters/feedback/inven/monitoring/sites/youtube 관련 controller·service·guard·config + `repositories/` 하위 4개 repo.

**외부 참조 (blast radius)**:
- `app.module.ts` → `./admin/admin.module` (AdminModule) — 경로 유지됨
- `main.ts` → `./admin/admin-monitoring.service` (`app.get(AdminMonitoringService)`) — **import 경로만 변경 필요**

**의존관계 정리**:
- 공유: `admin.guard.ts`(AdminGuard·AdminWriteGuard, AdminAuthService 의존) — 거의 모든 controller가 사용
- Prisma·Redis·Config 모듈은 전역(@Global/isGlobal) → import 불필요
- SitesModule(SitesService·SitesRepository) → sites, inven 사용
- StreamersModule(StreamersService) → youtube 사용
- FeedbackModule(FeedbackRepository) → feedback 사용
- site-extractor·site-suggest 서비스는 이름과 달리 **inven** 파이프라인에서 사용됨

**client 영향**: client는 별도 Next.js 앱, HTTP URL(`@Controller` 경로)로만 통신. 경로 문자열을 그대로 유지하면 client router 변경 **불필요**. (계획서에서 명시 예정)

**계획 방향**: 기능별 8개 서브 NestJS 모듈로 분리 (auth/cache/characters/youtube/sites/feedback/monitoring/inven). guard·AdminAuthService는 auth 모듈에서 export, 나머지 모듈이 import. 상세 계획은 사용자 승인 대기.
