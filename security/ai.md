# OWASP GenAI 보안 — AI 애플리케이션 보안 리스크

> OWASP GenAI Security Project가 관리하는 AI 애플리케이션 보안 리스크 정리.
> AI 시스템이 발전하면서 **LLM(기반 모델·RAG)** 과 **Agentic(자율/멀티에이전트)** 두 가지 상호보완 프레임워크로 분리됨.

---

## 1. OWASP Top 10 for LLM Applications

기반 모델·검색(RAG) 파이프라인과 상호작용할 때 내재된 취약점에 초점.

| 코드 | 이름 | 설명 |
|------|------|------|
| **LLM01** | 프롬프트 인젝션 (Prompt Injection) | 악의적 입력으로 모델이 시스템 지시를 무시하거나 내부 데이터를 유출하도록 조작 |
| **LLM02** | 안전하지 않은 출력 처리 (Insecure Output Handling) | LLM 생성 출력을 검증 없이 하위 시스템에 전달 → XSS, 명령 실행 위험 |
| **LLM03** | 학습/파인튜닝 데이터 오염 (Data Poisoning) | 데이터셋에 악성 예제 주입 → 모델 행동 편향 또는 백도어 |
| **LLM04** | 모델 서비스 거부 (Model DoS) | 비정상적으로 많은 연산·API 자원을 소비시켜 예상치 못한 비용 유발 |
| **LLM05** | 공급망 취약점 (Supply Chain) | 서드파티 모델, 변조된 의존성, 취약한 임베딩 |
| **LLM06** | 민감 정보 노출 (Sensitive Information Disclosure) | 학습 중 기억된 PII·내부 로직·기밀 비밀값 유출 |
| **LLM07** | 안전하지 않은 플러그인 설계 & 시스템 프롬프트 유출 | 권한 관리가 부실한 툴 플러그인, 숨겨진 시스템 프롬프트 노출 |
| **LLM08** | 과도한 자율성 (Excessive Agency) | 사람 검토(human-in-the-loop) 없이 AI에 너무 많은 자율 권한 부여 |
| **LLM09** | 벡터 & 임베딩 약점 (Vector & Embedding Weaknesses) | RAG 특유 결함 — 임베딩 역추론, 검색 우회, 테넌트 간 데이터 누출 |
| **LLM10** | 무제한 소비/허위정보 (Unbounded Consumption/Misinformation) | 환각(hallucination) 등 생성 오류, 모니터링 안 된 예산 초과 지출 |

## 2. OWASP Top 10 for Agentic Applications

계획·툴 호출·다른 에이전트와 통신하는 자율 AI 시스템 특유의 오케스트레이션 리스크 (코드: **ASI**).

| 코드 | 이름 | 설명 |
|------|------|------|
| **ASI01** | 에이전트 목표 탈취 (Agent Goal Hijack) | 공격자가 에이전트의 핵심 목표를 덮어씀 |
| **ASI02** | 툴 오용 (Tool Misuse) | 허가된 툴(API·DB)이 안전하지 않거나 의도치 않은 동작을 하도록 유도됨 |
| **ASI03** | 신원 & 권한 남용 (Identity and Privilege Abuse) | 에이전트가 권한을 과도 상승시키거나 자격증명을 부적절하게 공유 |
| **ASI04** | 에이전트 공급망 취약점 (Agentic Supply Chain) | 서드파티 프레임워크·외부 API 플러그인에 대한 동적 런타임 의존성 |
| **ASI05** | 예기치 않은 코드 실행 (Unexpected Code Execution) | 에이전트 툴체인을 통한 안전하지 않은 코드 평가·생성 |
| **ASI06** | 메모리 & 컨텍스트 오염 (Memory & Context Poisoning) | 장기/단기 메모리에 기만적 데이터를 심음 |
| **ASI07** | 안전하지 않은 에이전트 간 통신 (Insecure Inter-Agent Communication) | 멀티에이전트 통신·핸드오프 중 데이터 변조 |
| **ASI08** | 연쇄 장애 (Cascading Failures) | 감염된 에이전트 하나가 연결된 AI 시스템 전반에 도미노 효과 유발 |
| **ASI09** | 인간-에이전트 신뢰 악용 (Human-Agent Trust Exploitation) | 에이전트에 대한 과신 → 사람이 치명적 비즈니스 행위를 승인 |
| **ASI10** | 불량 에이전트 (Rogue Agents) | 오작동·조작으로 에이전트가 기업 경계를 벗어나 독자적으로 작동 |

## 3. AI Red Teaming (AI 레드팀)

### 개념

- **정의**: 공격자 관점에서 AI 시스템을 **의도적으로 공격·악용 시도**하여 배포 전에 취약점·유해 행동을 찾아내는 사전 점검 활동.
- 전통 보안 레드팀(네트워크·인프라 침투)과 달리, **모델의 입출력 행동 자체**(프롬프트 조작, 유해 콘텐츠 생성, 정보 유출 등)를 표적으로 함.
- 목적: 위 OWASP LLM/ASI 리스크가 **실제로 터지는지** 공격 시나리오로 검증 → 가드레일·필터·정책 보완.

### 주요 공격 기법 (테스트 벡터)

| 기법 | 설명 |
|------|------|
| **프롬프트 인젝션** (Direct) | 사용자 입력에 "이전 지시 무시하고 ~해라" 등 주입 (LLM01) |
| **간접 프롬프트 인젝션** (Indirect) | 웹페이지·문서·RAG 문서 등 모델이 읽는 외부 데이터에 악성 지시 숨김 |
| **탈옥 (Jailbreak)** | 역할극(DAN)·가상 시나리오·인코딩으로 안전 가드레일 우회 |
| **민감정보 추출** | 시스템 프롬프트·학습 데이터·다른 사용자 데이터 유출 유도 (LLM06/07) |
| **데이터 오염** | 학습/RAG/메모리에 악성 데이터 주입 (LLM03/ASI06) |
| **유해 콘텐츠 유도** | 폭력·차별·불법·위험물 제조 등 정책 위반 출력 유도 |
| **편향/환각 유발** | 차별적 응답, 사실과 다른 정보 확신 있게 생성 (LLM10) |
| **툴/에이전트 오용** | 에이전트가 권한 밖 API·코드 실행하도록 유도 (ASI02/05) |
| **다국어/난독화 우회** | 외국어·은어·base64·유니코드 변형으로 필터 회피 |
| **멀티턴 공격** | 여러 대화 턴에 걸쳐 점진적으로 유도 (단일 턴 필터 우회) |

### 진행 방식

1. **범위/위협 모델 정의** — 무엇을(모델·RAG·에이전트), 어떤 위험을(유출·유해출력·오용) 테스트할지.
2. **공격 시나리오 작성** — 위 기법별 프롬프트 셋(테스트 케이스) 준비.
3. **수동 + 자동 레드팀 병행**
   - 수동: 창의적·맥락적 공격(사람이 직접).
   - 자동: 대규모 프롬프트 자동 생성·반복 (도구 활용).
4. **결과 분류·심각도 평가** — 어떤 공격이 통했는지, 영향도 산정.
5. **완화 적용** — 가드레일·입력검증·출력필터·시스템프롬프트 강화·정책.
6. **재테스트(회귀)** — 패치 후 같은 공격 재시도로 막혔는지 확인. 지속 반복.

### 완화 / 방어 (테스트로 검증할 대상)

- 입력 검증·필터링 (악성 패턴·인젝션 탐지)
- 출력 필터링·모더레이션 (유해 콘텐츠 차단, OWASP LLM02 출력 처리)
- 시스템 프롬프트 분리·강화 (사용자 입력과 권한 경계)
- 최소 권한 (에이전트 툴 권한·human-in-the-loop, LLM08/ASI03)
- 레이트 리밋·비용 한도 (LLM04/10 — DoS·예산 폭주)
- 로깅·모니터링 (이상 프롬프트·탈옥 시도 탐지)

### 참고 도구 / 프레임워크

- 자동 레드팀/스캐너: **Garak**, **PyRIT**(Microsoft), **Promptfoo**, **Giskard**
- 가이드: OWASP GenAI Red Teaming, NIST AI RMF, MITRE ATLAS(AI 위협 매트릭스)
